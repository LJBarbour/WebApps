CIF Splitter

User Guide

Takes CIF files that hold several structures (data blocks), or whole folders and ZIP archives of CIFs, and saves each structure as its own .cif together with the SHELX .res, .hkl and .fab files embedded in it. Everything runs locally in the browser; no data leaves this page.

Quick start

  • Drop CIF/FCF files, a folder or a ZIP archive anywhere on the page. Alternatively click the drop area to browse (several files can be selected at once) or use or choose a folder….
  • Subfolders at any depth and ZIP archives, including ZIPs inside ZIPs, are searched. Anything that is not a .cif, .fcf or .zip is ignored.
  • Tick what you want to keep, choose how to save it (below) and press the button at the bottom. Dropping new files replaces the current list.

What you see

  • Every data block (data_NAME) is a structure and has its own card. When several files were found, the cards are grouped under the file they came from, with its path. Files inside a ZIP are shown as if the ZIP were a folder.
  • Under each structure, four chips show what can be saved: CIF (always) and RES, HKL and FAB when the CIF contains those SHELX files (the _shelx_res_file, _shelx_hkl_file and _shelx_fab_file items). A greyed chip with a dash means that file is not there.
  • The bar above the list gives the number of files found; “(N skipped)” counts files that could not be read or contained no data blocks. The line below it gives the number of structures.

Choosing what to save

  • Structure checkbox (beside data_NAME): include or leave out the whole structure. Leaving it out greys its chips but remembers their ticks, so ticking it again restores exactly what you had.
  • Chip checkboxes: choose which files of an included structure are saved, for example untick HKL to save only the .cif and .res.
  • Shift + click on a chip: applies the change to every structure for that file type. Shift-click a ticked RES chip and every RES chip is unticked; shift-click an unticked one and every RES chip is ticked. Structures that are currently left out are not touched. Hovering over a chip reminds you.
  • Select all / Deselect all (above the list) includes or leaves out every structure. It never changes the chip ticks.
  • The button shows how many structures will be saved (for example “Extract 3 of 12 structures to ZIP”) and is disabled when nothing is selected. A structure whose chips are all unticked counts as not selected.

Save as

  • ZIP archive: everything goes into one .zip, named after the CIF (name_split.zip) or after the dropped folder or ZIP (folder_split.zip; CIF_batch_split.zip if neither applies).
  • Files in a folder: you choose a folder and the files are written straight into it, with no ZIP. If any file would replace one that is already there you are asked first, and Cancel writes nothing. This needs Edge or Chrome (the option is greyed out otherwise), and the browser may refuse some system folders such as Downloads itself; pick a folder inside it instead.
  • The save dialog opens beside the file you dropped, or inside the folder you dropped (a web page cannot open the folder above it). If neither applies it opens in Downloads.

Folder layout

These options appear when there is more than one way to arrange the files: several structures in one CIF, several files, or files in subfolders. The example paths under each option are built from your own files.

  • Keep folder structure, one folder per structure: the dropped folders are mirrored, each source CIF gets a folder named after it (when there is more than one file) and each structure of a multi-structure CIF gets its own folder inside that, for example MOFs/sample/ALPHA/ALPHA.cif.
  • Keep folder structure, structures together: the same, except the structures of one CIF share that CIF’s folder, for example MOFs/sample/ALPHA.cif.
  • One flat folder: no subfolders at all; every file sits side by side. If two files would get the same name the second becomes NAME_2, then NAME_3 and so on.
  • When you save to a folder, One flat folder is preselected so the files are written exactly as they are. Choose one of the other layouts to have subfolders created inside the folder you picked. Switching back to ZIP restores your earlier choice.

The files you get

  • Files are named after the structure: data_ALPHA gives ALPHA.cif, ALPHA.res, ALPHA.hkl and ALPHA.fab. Characters not allowed in file names (/ \ : * ? " < > |) and spaces become underscores.
  • The .cif is the complete data block of that structure, with the embedded files left in it. The .res, .hkl and .fab are the embedded text on its own. The .hkl and .fab end at the 0 0 0 terminator record; anything after it is dropped.
  • All files are written with Windows (CRLF) line endings.

Limits and tips

  • ZIP archives are searched up to four levels deep and up to 5000 CIFs. Encrypted or damaged archives are skipped and reported.
  • A file that cannot be read is skipped rather than stopping the rest. Details of what was skipped appear in the browser console (F12).
  • The page loads its ZIP library from the web, so reading and writing ZIPs needs an internet connection; saving loose files to a folder does not.
