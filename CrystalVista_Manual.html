1. Introduction

CrystalVista is a single self-contained HTML file — no installation, no server, no build step. It opens in any modern desktop browser (Chrome or Edge give the fullest feature set, since they support the File System Access API used for folder-based batch processing and direct-to-disk saving; other browsers fall back to ordinary downloads). It is built for crystallographers and materials researchers working with porous host structures — metal–organic frameworks, zeolites, inclusion compounds, clathrates — who need to build a structure out from its asymmetric unit by crystallographic symmetry, separate a host framework from an included guest, and quantify the empty space (voids and channels) inside it.

Three ideas run through the whole app and are worth knowing before anything else:

  • Host and guest are independent layers. Loading a CIF/.res/.ins file gives you a host. A guest (an included solvent molecule, a gas, a templating cation) is created by selecting atoms already present and moving them into their own guest layer — there is no separate guest file. Deleting, hiding, or recolouring one layer never touches the other.
  • Growth, not a fixed molecule. A loaded CIF shows only its asymmetric unit at first. Everything else — a whole molecule, a coordination sphere, a full unit cell, an extended framework — is built outward from that by explicit symmetry operations (the Grow panel), and can be undone or deleted again like any other edit.
  • Void/channel analysis works on whatever is currently host. Guest atoms are always excluded from the void/channel search, so an included guest never masks the cavity it sits in. The calculation can run either on a symmetry-completed unit cell (the normal case) or on whatever host atoms happen to be grown and visible at the time (a narrower, non-periodic mode for exploring a partially built structure).

This manual follows the app's own panel layout (Structure, Style, Display, Void/Channel Analysis, Molecular Surface, Selection & Geometry, Macro, Visual Effects, Export) and adds three appendices: a full keyboard shortcut table, a full macro command reference, and a technical description of the void/channel algorithm for anyone who wants to know exactly what a reported volume means.

2. Getting started

Open CrystalVista.html in Chrome or Edge. There is nothing to install and no internet connection is required once the file is open.

  1. Load a structure. Drag a .cif, .res, .ins, or .xyz file onto the 3D view. This becomes the host and, for a CIF or SHELX file, starts symmetry mode: only the asymmetric unit is shown at first. An .xyz file has no symmetry information to start from, so it loads as a plain, already-complete molecule instead.
  2. Grow the structure. Open Structure > Grow and either click atoms with grow mode on (Mouse tab), or use Pack/Symmetry for an explicit range or operation, until the structure looks the way you want — a single molecule, a coordination sphere, a full unit cell, or an extended framework.
  3. Separate a guest, if there is one. Select the atoms belonging to the guest (e.g. a solvent or templating molecule) and use Move selection to > New guest group (Structure > Edit atoms).
  4. Style it. Use Style > Atoms and Style > Bonds for colours, radii, and bond thickness; Display for the unit cell, camera mode, and view direction.
  5. Analyse the void/channel space from Void / Channel Analysis — see Section 9.
  6. Save your work. Export > Save model... writes everything (both atom layers, symmetry data, void/channel results, display settings, camera position) to a single JSON project file that can be reopened exactly where it was left off.
TipA project JSON file is also the only format that remembers which atoms are host and which are guest — a plain CIF never does. If you plan to batch-process a folder of structures with a macro that needs that distinction, save each one as a project file first (see Section 13).

Camera modes

Three mutually exclusive modes (Visual Effects > Scene): Orthographic (default) is a true parallel projection — unit cell edges viewed straight down an axis overlay exactly, at the cost of a known artifact where zooming in close enough can clip through a solid atom (inherent to true orthographic projection, not a bug). Pseudo-orthographic and Depth scaling both use a genuine perspective camera parked far away at a narrow field of view, eliminating that clipping at the cost of very slight perspective convergence; Depth scaling exposes the angle as its own slider (up to 25°) for a deliberately stronger sense of 3D depth on a large structure. The chosen mode and angle, the background colour and the whole lighting setup (Visual Effects > Lighting) are remembered between structures and when the app is closed and reopened, and loading a saved project file does not change any of them.

4. Loading structures, symmetry, and growth

4.1 Loading a CIF, .res, .ins, or .xyz file

Dropping a .cif onto the 3D view loads it as the host and starts symmetry mode — it replaces any previously loaded host and clears the current guest along with it. There is no separate guest file: a guest is created from the same loaded structure by selecting its atoms and using Move selection to > New guest group. A CIF holding more than one structure (e.g. a CSD/Conquest search result with several data_XXXX blocks) loads its first entry and shows a Navigator with prev/next buttons and a dropdown for switching between the rest.

A SHELX .res or .ins file works identically from that point on — both formats are read into the same unit cell + symmetry operators + asymmetric unit representation internally. The one difference: Save CIF stays disabled afterwards, since there is no original CIF text to splice edits back into. A PART n instruction is read and remembered per atom: automatic bonding never bonds two atoms with different, both non-zero PART numbers (SHELX's convention for mutually exclusive disorder components); a negative PART number additionally suppresses bonding, across symmetry, to a grown copy with any non-zero PART number. Shift+Ctrl+Alt+click selects every displayed atom sharing the clicked atom's PART number (SHELX-derived structures only).

Dropping a CIF reads the unit cell, the symmetry operators from the file's own symmetry loop, and the asymmetric unit, then displays just the asymmetric unit. If the file actually contains a whole completed molecule (some CIF exporters do this), the extra symmetry-equivalent copies are detected and removed automatically so only the true independent set is shown. An atom on a special position (mirror, inversion centre, rotation axis) is never duplicated when a symmetry operation maps it onto itself or an already-present copy.

An XMol .xyz file — a bare atom count, a title line, then one element x y z row per atom in Cartesian Ångströms — drops in the same way but loads as a plain molecule with no unit cell and no symmetry operators, since the format simply doesn't carry that information. The Grow panel, Fill unit cell, Forget symmetry, and cell-mode void/channel analysis are all unavailable for an XYZ-loaded structure, exactly as they are after Forget symmetry is used on a CIF/RES-derived one; Save CIF likewise stays disabled. Everything else — display style, bonding, selection, molecular surfaces, molecular-neighbourhood-mode void/channel analysis, export — works normally.

4.2 The Grow panel

Grow appears once a CIF (or .res/.ins) is loaded, split into four tabs.

Mouse

The large button turns grow mode on or off. Two independent choices control how a click grows the structure: Bonds (the new atom must be covalently bonded to the clicked one, searched up to 5 unit cells away) or Sphere of inclusion (every symmetry-equivalent atom within a given radius, regardless of bonding — useful for a coordination sphere or a non-covalent solvent shell). Separately: Atoms adds just the newly connected atom; Fragment (default) adds the whole covalently-connected molecule within the asymmetric unit; ASU adds the entire asymmetric unit under whatever symmetry operation connects it. The Fragment/ASU distinction matters when the asymmetric unit holds more than one physically separate molecule (e.g. host and guest together) — ASU grows both since they share the transform; Fragment grows only the one actually clicked.

Pack

Grows by an explicit fractional-coordinate range (a, b, c each 0–1 by default, extendable to −5…5) instead of a click, with a choice of whether a fragment qualifies when a fragment atom or its centroid falls within the range. Every matching symmetry-related copy of the asymmetric unit is added as a whole covalently-connected fragment in one step.

Symmetry

Applies one explicitly chosen symmetry operation to whichever atoms are currently selected. The dropdown lists every space-group operator as the CIF itself expresses them; choosing one fills in the 3×4 matrix (rotation coefficients, always −1/0/1, plus translations). Each row also has its own −a/+a, −b/+b, or −c/+c pair for an immediate whole-cell shift along that axis. Use M-1 carries out the matrix in reverse; Select new selects each generated image in place of the source atoms (which is what makes repeatedly pressing a shift button walk outward one cell at a time); Keep source format copies each newly generated image's colour/radius directly from the atom it was generated from.

Molecular neighbourhood

A preview-first way of growing, for a framework or polymer that could extend in more than one direction. Enter a sphere-of-inclusion radius and turn the mode on: every not-yet-displayed symmetry-generated atom within that radius of something already shown appears as a small preview sphere (black by default, or coloured like the real atom with "Black nodes" unticked), joined by a dotted line to whatever it's close to. Clicking one adds the whole connected fragment it belongs to (Fragment-unit growth), and the preview refreshes around the newly larger structure. Nothing about the preview spheres is kept when the mode is turned off.

Settings for new host / guest atoms

Two dropdowns in the Grow panel decide the look a newly grown atom starts with, separately for the host and guest layers. Default leaves no override (plain ball-and-stick, CPK colour). Current style gives every new atom whatever Style > Atoms' Colour and Radii checkboxes currently hold. Same as ASU gives each new atom the look of its own asymmetric-unit parent atom — colour (CPK or custom), radius setting, and sphere-or-ellipsoid choice — so a symmetry copy always matches however its parent has been styled; a parent that has since been moved to the guest layer is still found, and an atom with no parent to copy from gets the Default look. The choice only applies at the moment of growth; atoms already present are never revisited.

Global growth helpers

Extend fragment(s) applies Mouse's Bonds+Fragment behaviour to every atom currently displayed in one step (only atoms present at the moment it is pressed are used as starting points, which is what stops a polymer or chain running away indefinitely). Complete molecule(s) fills out any partially-present fragment into a whole discrete molecule by symmetry, stopping cleanly at a genuinely polymeric/infinite fragment rather than trying to complete something that never ends; for a coordination polymer it also tops up a bridging ligand truncated by ordinary growth without pulling in a new metal centre. Generate whole molecules (off by default) runs that same completion automatically after every growth action. Delete all symmetry-generated atoms removes everything growth has added, back to the bare asymmetric unit.

Forget symmetry permanently discards a structure's symmetry information: every atom present stays exactly where it is, but growth, ASU-only display, and all symmetry-linked cascades stop working, and every atom can then be edited completely independently. This cannot be undone and asks for confirmation.

4.3 Host and guest layers

Loading a new host CIF starts fresh, clearing any guest along with the old host. Within one loaded structure, host and guest stay independent: deleting or hiding atoms in one layer never affects the other. Remove host and Remove all guests each ask for confirmation, since for a CIF-based structure they permanently delete the relevant asymmetric-unit atoms and everything grown from them.

A structure can also be loaded as one combined file and split afterwards: select the atoms belonging on the other side, choose a destination (Host, an existing guest component, or "New guest group") from the dropdown, and press Move selection to. This is also how a disordered guest with more than one component is separated — move one component's atoms at a time into successive new guest groups. Guest components are listed on the Guest tab with an atom count, a show/hide checkbox, and a "Select" button for the whole component; an empty component (everything moved or deleted out of it) disappears from the list automatically, with the remaining ones renumbered.

Growth remembers a host/guest split: once part of the asymmetric unit has been moved to a guest, every future symmetry-generated copy of that same asymmetric-unit atom is added as a guest too, joining the same guest component rather than starting a new one each time.

Every one of these toggles based on whether the clicked atom is currently selected, so repeating the same click on an already-selected atom deselects the matching set. Delete selection removes the selected atoms from whichever layer they belong to.

Normalising hydrogen positions

In Structure > Edit atoms, Normalise H atoms corrects the hydrogen positions of an X-ray structure. X-ray H atoms sit about 0.1 Å too close to their parent atom, which matters for anything that measures space next to H (voids, channels, close contacts). Each H atom is moved along its existing X–H direction to a typical neutron-diffraction distance: C–H 1.083, N–H 1.009, O–H 0.983, B–H 1.19, S–H 1.34 Å (after Allen & Bruno, Acta Cryst. B66, 380, 2010). The five boxes above the button hold these values, can be edited, and are remembered between sessions.

The parent is the nearest non-H atom within 1.45 Å, symmetry images included. An H with two parents at similar distances (a bridging H), with no parent in range, or on a parent element with no distance set, is left unchanged and the status line reports how many. The command acts on the selected H atoms, or on every H atom when none is selected; Undo restores the old positions. For a CIF-based structure the change is made on the asymmetric-unit site, so every symmetry copy moves together and the symmetry stays exact. The macro command is NORMALISE_H.

Cutting and forcing bonds

Click directly on a bond to select it, then Cut selected to sever it — the one tool for the case nothing automatic can fix: two atoms sitting a normal bond length apart that shouldn't actually be connected (most often two overlapping disorder components). For a CIF-based structure, cutting a bond cuts every symmetry-equivalent copy of it too. Delete matching bonds does the same in bulk by element pair and distance range. The Interactive bond editor (Structure > Edit bonds) additionally allows forcing a bond into existence between two atoms that aren't actually close enough to bond, by clicking them in sequence.

Show H bonds

When on, every displayed atom is scanned for probable hydrogen bonds, drawn as a short red dashed line. This is a geometric estimate (donor: a hydrogen bonded to exactly one N/O/S/Cl; acceptor: any other N/O/S/Cl within a plausible, roughly linear contact distance) — the same two-criterion first pass tools like Mercury use, not a quantum-mechanical calculation.

Undo, symmetry consistency, and special cases

A single shared undo history (Structure > Edit atoms or Edit bonds, either button) steps back through moving atoms, deleting atoms, and cutting bonds. Ctrl+Z does the same from the keyboard (the Windows convention). It does not cover loading files or element/display settings, which have their own separate resets.

For a CIF-based structure, an atom's element and its host/guest membership are properties of the asymmetric-unit position, not of one particular symmetry image of it — changing either on any one image applies automatically to every other currently-displayed image of that position. Deletion is the one exception handled two ways on purpose: deleting the untransformed (asymmetric-unit) copy of a position removes it entirely, including every symmetry image, and growth will never regenerate it; deleting a symmetry-grown copy on its own is a purely local edit — the asymmetric-unit atom stays, and growing again nearby can recreate that same image later.

Show ASU only (or the a key) is a display filter only — it hides every symmetry-grown copy, has no effect on what is calculated or grown, and clears the selection on anything it hides.

Select two or more atoms and Generate centroid (or Ctrl+C) adds a small white marker at their average position, useful as a geometric reference; it can be selected, moved between host and guest, and deleted like any real atom, and (for a CIF-based structure) becomes part of the asymmetric unit for growth purposes. Reassign element to changes the element of the selected atom(s) to anything in the periodic table (picking up its own colour/radius immediately); reassigning a centroid turns it into a real atom of that element.

6. Selection & geometry, and selection groups

The Selection & geometry section shows a live readout for the current selection. More than 4 atoms selected shows a count and an element breakdown; for 1–4 atoms it shows the last-selected atom's element and coordinates, then builds up cumulatively — 2 atoms adds the distance between them, 3 adds the second distance and the angle at the middle atom, 4 adds the third distance, second angle, and the torsion through all four — sighting from the second atom to the third, positive means the near bond needs a clockwise turn to eclipse the far bond (the standard IUPAC convention, matching Mercury, Olex2, PLATON, and SHELX). The order used is the order the atoms were actually selected in — click them one at a time in the sequence that gives the reading you want (e.g. along a bond chain for a meaningful torsion); deselecting one and reselecting it moves it to the end of the order. Where a CIF gives coordinate uncertainties, a distance/angle/torsion is shown with its own propagated esd (untransformed atoms only, no cell-parameter or cross-atom covariance).

Selection groups

Remembers a named set of atoms so it can be re-selected later without picking them by hand again. Select whatever's wanted (host and guest can be mixed in one group), optionally name it, and press Save selection as group — this also clears the selection just saved, since the new group's own Select button brings the same atoms straight back whenever wanted. Each group row shows an editable name, a live count of how many of its atoms are still actually present, and Select/Deselect buttons that add/remove just that group's atoms without disturbing an unrelated selection in progress, so several groups can be combined by selecting each in turn. An atom can belong to any number of groups at once, independent of host/guest membership; once every atom a group ever referred to has been deleted, the empty group disappears automatically. Selection groups are saved as part of the project file, the same as guest groups.

7. Appearance: elements, atom style, and bonds

Elements: radii and default colours

The Elements page is a periodic table showing every element's van der Waals radius and default colour together, plus D and T (deuterium/tritium) for neutron structures that label them as their own species. Radius is shared between host and guest and used both for the atom display and the molecular-volume calculation. The built-in default is Bondi (A. Bondi, J. Phys. Chem. 1964, 68, 441); anything Bondi doesn't cover gets a flat 2.0 Å. Use Alvarez radii (S. Alvarez, Dalton Trans. 2013, 42, 8617) offers a published alternative covering most naturally occurring elements including transition metals. Save/Load element settings reads and writes a CSV (atomic number, radius, colour); radii and colours are also remembered automatically per-browser between sessions.

Atom style

Every atom is CPK-coloured by default unless given a Custom colour from Style > Atoms. Colour is CPK/Custom/neither (tri-state); Radius is Radii×vdW (separate Non-H and H multipliers) or a single Fixed radius, or neither — only a ticked property is touched by Apply. Three preset icon buttons set common combinations: Stick (fixed radius 0), Ball & stick (0.2×/0.15× vdW), Spacefill (1.0×/1.0× vdW) — Apply is still required afterwards. Copy settings loads a single selected atom's current look back into the checkboxes, for copying it onto another selection. The Guest tab's own colour by (Element/Component) sets guest colouring as a whole, with a per-atom Custom override still taking priority over either.

Bond thickness

Set directly in Å (default 0.12), independently for host and guest. Each atom sphere is sized from its own element's van der Waals radius unless overridden per atom, and is widened to match bond thickness if that would otherwise make it narrower than the bond feeding into it — a radius override of 0 collapses an atom all the way down to the bond's own thickness for a "stick-only" look. Bonds are drawn split-coloured (each half in its own atom's colour) by default, or a single colour per layer if chosen.

Unit cell and axis key

Style > Unit cell opens with a Show unit cell checkbox that echoes Display's checkbox of the same name and the c key — change any one and the others follow. Below it are Label axes (the a/b/c corner labels), RGB axes (colour the a/b/c edges red/green/blue), Cell colour and Line thickness — all of these, plus whether the cell is shown, are remembered between structures and when the app is closed and reopened. Each corner label sits genuinely at its corner in 3D and is occluded normally by anything nearer the camera, not painted on top of everything. A divider then separates the cell's settings from the axis key's: Show axis key (echoing Display's checkbox and the k key), Axis key zoom (scales the whole key — arrow length and thickness, arrowheads and letters alike), proportional lengths (arrow lengths follow the real a/b/c edge lengths; off = all equal), show labels a, b, c (a letter beside each arrow tip in the arrow's own red/green/blue on a transparent background, scaling with the key's zoom and positioned smoothly so it never jumps as the model rotates; on by default and remembered between sessions; included in exported images along with the key) and Reset key position. All of the key's settings — whether it is shown, where it was dragged, its zoom, proportional lengths and labels — are remembered between structures and when the app is closed and reopened (a saved project file still restores its own).

Atomic labels

Style > Atomic labels (moved here from Display, where it was called Labels) holds Show atom labels — echoing Display's checkbox and the l key — plus Contrasting outline, Font, Colour, Size, and the buttons that label/unlabel the selected atoms and unfix dragged labels.

8. Display settings and Walk mode

The Display section holds general settings (Show ASU only, Show atom labels, Show unit cell, Show axis key, Show hydrogen atoms, Show H bonds, Immobilise view, background colour, Centering with its Recenter button, Set scale) plus the nested Direction panel (view shortcuts along each cell axis/plane, a general [hkl] field, and View along vector / View perpendicular to plane — available once exactly 2 or exactly 3 atoms are selected respectively). The appearance of the unit cell, axis key and atom labels lives under Style (Section 7); the unit cell, axis key and atom-label checkboxes here are echoes of the ones there.

Clipping planes

A clipping plane (Display > Clipping Planes, up to six of them in a list) cuts away everything on one side of a plane so that the inside of a structure, void or channel can be seen. The tick box beside a plane in the list switches it on and the cut slider moves it from the near edge of everything loaded (0: nothing clipped) to the far edge (100: everything clipped), so the range scales itself to the structure; Invert clips the far side instead. Apply to selects what is cut: host, guest, voids, channels, molecular surface and unit cell (atom labels always follow the plane). The plane is either perpendicular to the view, turning with the model, or perpendicular to (hkl), fixed in the crystal, with the indices read as a plane normal or as a direction [hkl].

Solid cut faces (off by default, in addition to the usual look; a remembered preference with its own colour swatch, grey by default) closes the cut faces of clipped objects with a flat colour instead of leaving hollow shells with the bonds visible through the walls. The colour appears only where an object is actually cut, never across the whole plane. The tick boxes below it choose the kinds of object that get a solid face: Atoms and bonds, Voids, Channels and Molecular surface; a kind only gets one if the plane also clips it (the Apply to boxes), and atoms and bonds follow the Host and Guest boxes. For atoms and bonds the colour is laid down where the line of sight passes from the clipped-away region into a solid, so overlapping atoms and bonds fill as one; for voids, channels and the molecular surface the face is the plane's actual section through the surface, which does not depend on the viewing direction, stops at the unit cell face for a channel, and covers the whole cross-section of a void. The face of a void, channel or molecular surface is drawn on both sides, so it can be seen from either side of the plane (through a translucent surface, or from the kept side of a surface that has been cut open); the face of atoms and bonds is solid, so from the kept side you see the atoms themselves, not the inside of the cut. Labels and the unit cell are never filled. The faces are included in exported images and videos. With Invert on the cut faces lie on the far side of the objects and are seen by turning the model round. A very small solid disc can appear where the plane just grazes an atom, most noticeably a white hydrogen on a white background: it is that atom's cut face.

Several planes. The Clipping Planes submenu holds a list of up to six planes. Each row has a tick box that switches that plane on or off, its name and a small chip showing the colour of its solid faces; click a row to select it. Add plane makes a new plane that starts with the selected plane's settings (so a parallel slab is one click and one position change), and Remove plane deletes the selected one. The controls below the list — name (type to rename), cut slider, position and step, invert, solid faces and colour, Apply to, orientation — always belong to the selected plane, and every plane keeps its own set. Where several planes are enabled an object is cut away if any plane removes it, so planes together can cut out a slab, a wedge or a corner; each has its own solid colour, and a solid face never shows where another plane has already removed the object. The list, names and settings are remembered between sessions (which planes are switched on is not).

Fine positioning. One step of the slider is 1% of the structure's width, a few tenths of an Ångström. The position box under it gives the plane's distance from the centre of the view along its normal (negative = nearer the viewer); type a value or use its arrows, which move the plane by the increment chosen in step (1, 0.1, 0.01 or 0.001 Å). With the slider focused (as it is after a click on it) the cursor keys move the plane by the same step (default 0.1 Å), and Shift with a cursor key moves it ten times as far. The slider and the box are always in step.

Walk mode

A separate, free-fly first-person view for exploring the inside of a void or channel — a different way of looking at the structure entirely, not a variation on the ordinary orbit view. Turning it on drops the camera into the scene exactly where the orbit view was last looking; turning it off returns instantly to that same orbit view.

Both drags use the app's own "grab and drag the scene" convention (drag right = the view moves as if the structure were pushed right), matching the ordinary orbit view rather than a first-person-shooter's "push the mouse to turn your head" — Reverse drag directions flips looking-around (not panning) for anyone who prefers it the other way. Recenter view snaps back to the exact view Walk mode was entered from. Walk speed, Pan sensitivity, and Swivel/roll sensitivity are independent. Headlamp is a light that travels with the camera, off the instant Walk mode is left.

Collision detection (off by default) stops the camera at whatever is currently drawn, governed by its own "Collide with" checklist — Host/Guest atoms and bonds, Voids/Channels, Molecular surface, and Coordination polyhedra, all on by default. For void/channel surfaces specifically: collision matches exactly what is rendered on screen, including a clip-plane cut at a cell face (never a missing wall, occasionally a slightly larger one right at the boundary) and a periodic channel's own single rendered period — its own repeats are not conjured up just for collision, so a channel that has not been manually copied (Fragments panel > Move/Copy) will have walkable open ends where the next period would be.

9. Void and channel analysis

This is the app's core analytical feature: finding the empty space — voids (finite pockets) and channels (space that repeats endlessly along one or more cell axes) — inside a loaded structure, using van der Waals radii and a probe radius the same way the molecular-volume calculation does, but reporting the space itself rather than the atoms' own volume. Guest atoms are always excluded, so an included guest never masks the cavity it occupies.

Two modes

Fill unit cell silently completes the whole unit cell from the CIF's own symmetry and searches that, regardless of how much is actually grown on screen — this is the normal, periodic mode. Use grown atoms only instead searches only whatever host atoms are currently displayed, with no unit-cell boundary and no periodicity, so growing more or less of the structure changes the result, and a probe that can escape the grown structure entirely is never reported as an enclosed void.

Running a calculation

Calculate populates the results table (one row per region, with its stability limit, swept volume, and the surface itself) and draws the corresponding surfaces in the 3D view; Clear all removes them. Loading a new structure or project always clears previous results automatically. Additive (keep previous results), unticked by default, controls whether a fresh Calculate replaces everything (the default) or adds its newly found regions to whatever is already on screen, leaving every earlier region's colour, visibility, and fragment state untouched — useful for comparing two probe radii side by side.

Reading the results table

Limit reports, for each component, how sensitive its void/channel classification is to the probe radius actually used. For a channel, shown as “≤ R” — the largest probe radius it would still be recognized as this same connected channel at; above it, part of the channel gets pruned away into separate void(s) or removed. For a void, shown as “≥ R” — the probe radius below which it would connect to a periodic image of itself and become a channel; a dash means it stays a void down to the practical floor tested (0.05 Å). In "Use grown atoms only" mode this is always a dash, since that mode has no periodic images to connect to.

The reported volume always has some grid-discretization error, more pronounced for a small cavity than a large one. Accurate volumes (extrapolated, slower) corrects for this — see Appendix C for exactly how — at the cost of roughly six times the calculation time.

Assemble & Consolidate (on by default) automatically reassembles a void/channel's edge/corner fragments into one whole piece nearest the origin and bakes that arrangement in permanently, the same as the Fragments panel's own manual buttons.

Known limitationsA very small void (a handful of nodes) can show a noticeably different reported volume between otherwise symmetry-equivalent copies of itself — grid-discretization noise, not a real difference; Accurate volumes resolves it. A channel periodic along more than one non-Cartesian-pure axis at once (a genuinely oblique/triclinic cell) can show a real, visible seam where two Fragments-panel pieces join end-on, and may need the Fragments panel used by hand rather than relying on Assemble & Consolidate.

Colour, opacity, fragments, and copies

Colour is set at three levels of precedence: a global "Same colours for all voids/channels" link, then a per-instance colour (an instance being the original or any Move/Copy/Recolour-made copy), then a fixed palette default. Opacity works the same three-level way, entirely independently of colour. A void/channel sitting at a cell edge or corner is shown as several complementary fragments, listed in the Fragments panel; Assemble moves them back onto each other, Consolidate bakes that into one permanent piece. Move/Copy/Recolour offers three mutually exclusive modes for repositioning, duplicating by translation, or recolouring fragments/instances selected directly in the 3D view (see the in-app Guide for the full click/Shift/Alt/Ctrl selection scheme, which mirrors ordinary atom selection).

10. Molecular surfaces

A different, simpler tool from Void/Channel Analysis: a solvent-accessible "contact" surface computed directly over whatever atoms are currently selected (host and guest combined), with no concept of enclosure, volume, or topology at all — it is a shell over a chosen set of atoms, not an analysis of the space around them.

Select atoms, set a probe radius (0.01–3.0 Å, default 1.0), and press Calculate: a distance-transform grid is built and the isosurface at exactly that probe radius is extracted — the outer contact shell a sphere of that radius would trace rolling over the selected atoms' van der Waals surfaces — then relaxed with alternating-sign smoothing and reprojected back onto the true isosurface to remove voxel-grid stipple without leaving gaps. Calculate is additive: each press appends a new surface over whatever is selected at that moment, so several surfaces over different sub-selections can coexist, each independently listed (with its own visibility checkbox, atom count, probe radius, and colour) and independently deletable. The selection is cleared automatically once a surface is calculated. A single global opacity slider and a Same colour for all link apply to every surface at once, or each can carry its own colour.

All computed surfaces are cleared automatically when a new structure is loaded, but they do round-trip through a saved project file, and integrate with Walk mode collision (Section 8) as a thin shell using the exact triangle data drawn on screen.

NoteA probe radius smaller than the grid's own step size risks a contact band thinner than one grid cell; the grid step is scaled down automatically as the probe radius shrinks (down to a 0.02 Å floor), so a very small probe radius costs more to compute rather than producing a broken surface.

11. Coordination polyhedra

Draws a polyhedron over the ligand atoms coordinating each visible metal centre. For every currently-displayed metal atom, the app finds its full symmetry-derived ligand set using the same covalent-radius bonding test as ordinary bonds, takes the convex hull of those ligand positions, and draws only the hull faces whose three vertex atoms are all actually on screen right now — so a partially grown structure shows a partial polyhedron rather than requiring the whole coordination sphere first. Coplanar ligand arrangements (square-planar, the equatorial plane of a trigonal bipyramid, etc.) are re-triangulated as a clean fan rather than left as degenerate slivers, and haptic/ring ligands (e.g. a cyclopentadienyl bound as a whole π-system) are detected and excluded from the vertex set. A manually cut or forced bond (Structure > Edit bonds) changes the ligand set the same way it changes ordinary bonding.

Turned on from Style > Coordination Polyhedra: a single show/hide toggle (off by default), an opacity slider, an edge-thickness slider for the solid cylindrical edge spines, and a choice between colouring each polyhedron by its own central metal's current display colour, or one single shared colour. There is no manual central-atom picker — every visible metal (anything not classified as a non-metal) automatically gets a polyhedron whenever the toggle is on and it has at least three co-displayed ligands. Polyhedra are only ever computed for a loaded CIF with intact symmetry information; nothing is drawn for a non-CIF structure or after "Forget symmetry". Polyhedra integrate with Walk mode collision and with the clipping plane's own separate Host/Guest apply toggles (split by the central metal's own host/guest membership, not the ligands'), and settings round-trip through a saved project.

12. L.S. planes

Show planes, the first control in Style > L.S. Planes, is a single master on/off (on by default) that hides every plane at once without deleting any of them or disturbing each one's own individual show/hide checkbox in the list below — turn it back on and every plane reappears exactly as it was left.

Select three or more atoms (host and guest together) and New plane (enabled the moment the selection count reaches three; or just press the p key, which does exactly the same) fits and adds a least-squares mean plane through them — the plane through their centroid whose orientation minimizes the summed squared perpendicular distance to every one of the fitted atoms, exactly the same "best-fit plane" convention Mercury, PLATON, and SHELXL all report, not simply a plane fixed by any three of the atoms with the rest merely tested against it. Mathematically, the fitted normal is the eigenvector of the atoms' own 3×3 covariance matrix with the smallest eigenvalue, found with the same symmetric-matrix eigensolver already used elsewhere in the app for ADP ellipsoid principal axes; the two largest-eigenvalue eigenvectors span the plane itself. The rendered shape is a polygon through each fitted atom's own projection onto the plane, angularly sorted around the centroid — select the six atoms of a ring and the plane reads as a hexagon with its own vertices sitting right where the atoms are (exactly there if they're perfectly planar, very close otherwise), not a generic bounding rectangle. The selection is cleared automatically once a plane is added, ready to select a different group of atoms for the next one.

Planes accumulate in a list rather than replacing the previous one, mirroring Molecular Surface's own list exactly: each row shows its atom count and rms deviation — the root-mean-square perpendicular distance of the fitted atoms from their own best-fit plane, 0 meaning perfectly flat — with its own show/hide checkbox and colour swatch, or tick Same colour for all to colour every plane at once instead of individually; a single Plane opacity slider applies to all of them together. Clear all removes every plane in one step, and each row's own × button removes just that one.

NoteA plane is a one-time snapshot of the fit at the moment New plane is pressed — like a molecular surface, it does not track or refit itself if the atoms it was fitted from are later moved, grown further, hidden, or deleted. Planes round-trip through a saved project file, but (unlike element radii/colours and other look-and-feel settings) are not remembered between browser sessions on their own.

13. Macros and batch processing

A macro is a plain-text sequence of commands, one per line, recorded live from clicks and button presses, typed or pasted in by hand, or a mix of both. It is designed to work not just on the structure it was recorded against but on a whole series of similar ones — e.g. a variable-temperature data set for the same crystal — provided each structure's asymmetric unit is labelled the same way and sits in the same place (nothing here can verify that automatically).

Recording and playing

Record/Pause are mutually exclusive; while Record is down, every action with a defined macro command is appended to the memo the instant it happens, in the exact sequence performed — not every action has one, and an unrecorded one is simply skipped, silently. Save/Load read and write a plain-text .MAC file (also droppable directly onto the 3D view). Play runs every line in order against whichever structure is currently loaded, reporting how many ran versus how many failed by line number — an unrecognized command, or an atom reference that doesn't match anything in the currently loaded structure, is skipped rather than stopping the whole run.

Two buttons insert a command with no live equivalent action, regardless of Record: Add current POV (a VIEW command capturing the exact camera orientation) and Add EXPORT_PNG/Add SAVE_JSON (their own suffix textboxes alongside).

Batch-processing a folder

Apply macro to all files in folder turns Play into a batch operation: grant access to a folder, then press Play as normal. Every .cif/.res/.ins/.xyz/.txt/.json file in that folder is loaded in turn (alphabetical order) and the whole memo runs against each one before moving to the next. .json files are project files previously saved from this app (Save model, or SAVE_JSON itself) — the only format that actually distinguishes host from guest, since a plain CIF never does; sorting a structure's atoms into host/guest once by hand and saving that as a project is how to build a folder of files a host/guest-aware batch macro can process. A .zip project archive is deliberately not picked up by the folder scan — only plain .json.

Exporting from a macro

EXPORT_PNG [suffix] saves the current view as a PNG using the current Export > Image settings, named from the structure's own name plus the given suffix. SAVE_JSON [suffix] writes the current model out as a project file, the same complete payload Save model writes, respecting the Compress as zip checkbox the same way Save model does. With no suffix it overwrites the exact file the structure was loaded from (falling back to the structure's own CIF-derived name if it wasn't loaded from JSON); with a suffix it saves alongside as name_suffix.json (or .zip). Both commands write into a folder granted once per browser session (the batch folder itself, if batch mode is on, otherwise a one-time folder picker) with no further prompts.

Note on .zip output and batch input A SAVE_JSON that runs with Compress as zip ticked writes a .zip — which will not be picked back up by a later batch run over the same folder, since that folder scan only recognizes plain .json. Leave the box unticked for a "save now, batch-process again later" workflow.

CALCULATE_VOID and CALCULATE_VOID_Q

These press Calculate under Void/Channel Analysis exactly as if clicked by hand, using whatever probe radius and mode are on screen at the moment they play — with one deliberate exception. Accurate volumes is itself saved inside a project .json, so batch-processing a folder of them would otherwise have each file's own load silently reset that checkbox to whatever that particular file happened to have saved, making accurate-vs-quick effectively random across a batch rather than something the macro actually controls. CALCULATE_VOID therefore always forces Accurate volumes ON before calculating (and ticks the checkbox to match), regardless of what is currently set or what a just-loaded .json brought with it; CALCULATE_VOID_Q always forces it OFF, for the rarer case where a genuinely quick batch calculation is wanted. While Record is down, clicking the real Calculate button records whichever of the two matches the checkbox's own state at that moment, so replaying a recorded macro reproduces the exact accurate/quick choice that was live when it was recorded.

Each time either command plays, every region found is appended as its own row to the Void/channel batch results table in the Macro panel — Structure, ID, Type, Critical radius, Volume, and the probe radius in effect for that row — building one combined comparison table across everything processed so far this session. It is never cleared automatically; Copy as TSV/Save as CSV export it, Clear table empties it. An ordinary manual Calculate click never adds a row here.

NORMALISE_H

NORMALISE_H, when played, presses Normalise H atoms (Structure > Edit atoms), using the distances in the five boxes at the moment it plays. In folder-batch mode a whole series is one macro — for example NORMALISE_H followed by CALCULATE_VOID for every structure in a folder.

See Appendix B for the complete command reference.

14. Visual effects, rendering, and export

Visual Effects is split into three tabs: Scene (background, camera mode, detail level, fog, rotation sensitivity), Material (how atoms respond to light — roughness, metalness, reflection strength), and Lighting (key/fill/rim lights, each independently switchable, plus "Light follows view" and light angle). Each tab has its own "restore defaults" and its own "retain these settings" box (ticked by default, remembering that tab's settings between sessions per-browser).

High detail spheres & tubes swaps in finer tessellation at some cost to rotation smoothness for large structures. Export image (PNG) always renders at full tessellation regardless of that toggle, at a chosen resolution multiple, then restores interactive settings afterward. Transparent background applies to both image export and Copy image to clipboard. If Show axis key is on, it's drawn into the exported image too, at its current on-screen position, size, and orientation (a part overlapping the sidebar or header is clipped out, matching the live view).

Save model.../Load model... save or restore the complete working state — every atom, the CIF symmetry data, colour/radius overrides, bond/display settings, void/channel results, and the camera position — to a single JSON (optionally zip-compressed) file, distinct from the automatic per-browser memory of element radii and display preferences. This is the portable, permanent copy of a specific piece of work.

Video: rotation and rocking

Export > Video records the current view as a video. A choice at the top selects the kind: Rotation (one full 360° turn about a view axis, in the number of steps given) or Rocking (a swing back and forth, made to be played on a loop). The settings shown, and the label of the export button, follow that choice; fps, size and format (uncompressed AVI, or the much smaller MP4, which needs a one-time encoder download) apply to both. An axis is a view axis (+Y turntable, +X tumble, +Z roll) and a plus sign always means the right-hand-rule rotation of the model.

Appendix C — How void/channel space is calculated

This appendix describes the algorithm behind Section 9 in more depth than the in-app Guide does, for anyone who wants to know exactly what a reported region, classification, or volume actually means.

1. Building the void network: a weighted Delaunay tetrahedralization

Given the host atoms (Cartesian position and van der Waals radius each) and, in "Fill unit cell" mode, the unit cell, the app builds one periodic void network via a weighted Delaunay (regular) tetrahedralization, computed as the lower convex hull of the atoms lifted into 4D (the standard "paraboloid lifting" construction for a weighted Delaunay triangulation). Voids and channels are simply two classifications of that one network's connected components — there is no separate code path for either, and critically, no grid or resolution parameter enters into the topology or the void/channel classification decision at all. A probe radius only prunes an already-exact graph after the fact; it is never consulted while building it.

Why a regular triangulation, not a plain Voronoi diagram Atoms have unequal radii, so the physically correct "largest empty sphere" network is an additively-weighted (Apollonius) Voronoi diagram, whose cell boundaries are hyperboloids — a substantially harder computational-geometry problem to implement robustly. Following the same approximation used by established tools in this space (e.g. Zeo++), CrystalVista instead uses the power (radical) diagram, whose bisectors are ordinary planes, as a computationally tractable proxy: the network's topology (which cavities exist and how they connect) comes from the power diagram, but every reported radius is the true Euclidean distance to the nearest atom's own van der Waals surface — the physically meaningful quantity — not the power distance itself. The two coincide exactly only when the atoms defining a given vertex happen to share the same radius.

Each tetrahedron of the weighted triangulation corresponds to one vertex of the dual void network (a point equidistant, in the power-distance sense, from its four defining atoms) with a well-defined clearance radius. Two network vertices are joined by an edge when their tetrahedra share a face (three atoms in common); the connected components of this vertex–edge graph, after removing every vertex whose own clearance radius is smaller than the current probe radius, are exactly the candidate voids and channels. A component that closes up on itself within one unit cell is a void; a component whose own vertices span a full periodic repeat along one or more cell axes is a channel, with its dimensionality equal to the number of axes it is periodic along.

2. Probe-radius stability limits

The Limit column (Section 9) is found by binary search directly on this exact graph, not by re-running the whole calculation at many probe radii. For a channel, the search asks "at what probe radius does this component stop being connected across a full periodic repeat" — the largest radius at which it is still classified as a channel. For a void, the search asks "at what probe radius does it first connect to a periodic image of itself" — the smallest radius at which it would channelize. Both searches bisect between a practical floor (0.05 Å) and the probe radius currently in use, re-testing the component's own connectivity at the midpoint each iteration, converging to the stability limit in a fixed, small number of iterations regardless of network size.

3. From network to a reported volume: grid + Euclidean distance transform

The void network above gives topology and connectivity for free, at no resolution cost, but it does not directly give a swept volume — that still has to be measured geometrically. For each component, the app builds a local 3D grid over its own bounding region (padded for periodic completion where relevant), computes each grid cell's Euclidean distance to the nearest atom surface (a distance transform, not a naive per-cell atom scan), and counts every cell whose distance meets or exceeds the current probe radius as "swept". The reported volume is that cell count times the cell volume; the same distance field also drives the isosurface actually drawn in the 3D view (at distance = probe radius), so the number shown and the picture drawn can never disagree with each other.

Because this is a discretization, a coarser grid resolution systematically undercounts volume — a voxel straddling the true boundary is either counted whole or not at all, and this effect is proportionally larger for a small cavity than a large one (more of its volume sits near the boundary relative to its interior).

4. Accurate volumes: Richardson extrapolation to zero grid spacing

Accurate volumes (extrapolated, slower) addresses this directly rather than simply using a finer fixed grid. Each component is measured at six progressively finer grid spacings, and a straight line is fit to volume against spacing (V = V∞ + a·h); the reported value is the fitted V∞ — the volume the grid method would converge to at an (unreachable) zero spacing — with an uncertainty derived from the fit's own residual and its distance from the two finest directly-measured points. This is the same underlying quantity a rolling-probe program such as MSRoll reports directly, without needing a grid at all, and was checked against MSRoll's own output on a real structure: after linear extrapolation the two methods agree to within roughly 1–1.5%, a gap attributable to the two methods defining "swept volume" very slightly differently (rather than to any remaining discretization error in either one). A quadratic extrapolation model was tried and rejected during development — it moved the fitted value slightly further from the reference while making the reported uncertainty look smaller, which would have been actively misleading rather than more accurate; the straight-line model is used because it is the one whose own uncertainty estimate can actually be trusted.

5. What "Fill unit cell" completes, and what periodicity means for a channel's own picture

In "Fill unit cell" mode the atom set fed into steps 1–4 above is the host completed by the CIF's own symmetry across a padded neighbourhood of unit cells, not just whatever happens to be grown on screen — so the calculation is always run against the true, complete periodic structure regardless of how much of it is currently displayed. A channel's rendered surface, by contrast, is deliberately just one period's worth of wall by default (extra periodic copies are only added where display or Walk-mode collision genuinely need them, and even then only as a rendering/collision convenience, never by re-deriving the underlying network) — use the Fragments panel's Move/Copy to add further real, solid periodic copies for a figure or for Walk-mode exploration further along a channel's own length.

In short Classification (void vs. channel, and the Limit column) comes from an exact, resolution-independent geometric network and is never approximate. Only the reported volume is a numerical measurement with a controllable error, and Accurate volumes exists specifically to quantify and remove that error rather than just guessing at a finer grid.
