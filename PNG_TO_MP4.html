Guide

Loading a sequence

Drag the first image of the sequence anywhere onto the window. The browser then asks you to confirm the folder it sits in — that confirmation is unavoidable, because a dropped file gives a web page no way to see its neighbours. Dragging the folder itself skips that step.

Every PNG, JPEG, BMP, WebP, GIF or AVIF in the folder becomes one frame, in filename order. Sorting is numerically aware, so img_9 comes before img_10 even where the digit counts differ. Drop another image at any time to switch folders. There is no file-browser button anywhere: dropping is the only way in.

The preview

The main panel shows one frame exactly as the encoder will write it, embedded text included. Move through the sequence with the slider, the ‹ › buttons, or the arrow keys — Home and End jump to the ends.

The large play button runs the sequence at the chosen frame rate, so the timing can be judged before committing to a file; the spacebar does the same. It plays through once and stops on the last frame, and pressing play again from there restarts from the beginning. Any manual frame change takes over from playback. Smoothness on screen is limited by how fast the images decode, so large frames at high rates may not quite keep up — that affects only the preview, never the saved movie, whose timing is exact.

Embedded text

Each frame can carry its own filename, burnt in. The extension is dropped, so 120 K.png is drawn as 120 K. Name the files after whatever the sequence steps through — 100 K, 120 K, 140 K — and the movie labels itself.

A value run together with its unit is spaced out to scientific convention: 200K is drawn as 200 K, 12bar as 12 bar, 1.5GPa as 1.5 GPa, 25°C as 25 °C. This fires only when the whole name is a number followed by a unit, so ordinary filenames are never rewritten — 2024-01-15, frame_0001, 2x2 and 10x are all left exactly as they are.

Placing it: drag the text around the preview; the cursor becomes a hand as it passes over it. Only the text itself responds — clicking anywhere else on the image does nothing, so the label can never be moved by accident. X and Y can also be typed, and are measured from the top-left corner of the image. Size and position are in original-image pixels, so a layout set up here holds at any output percentage. reset restores a sensible default size and inset.

A contrasting outline is added automatically — dark behind light text, light behind dark — so the label stays readable over whatever it lands on, however the background changes through the sequence. Font, size and colour are yours to set.

Frame rate

Every image becomes exactly one frame; the frame rate decides how quickly they go past. Lower is slower. The readout underneath gives the resulting movie length.

Output size

A percentage of the original image size. Aspect ratio is always preserved, and the movie is never enlarged past the original — upscaling cannot add detail, only bytes — so 100% is the maximum. H.264 requires even pixel dimensions, so each side is rounded down to an even number.

An image whose dimensions differ from the first one is fitted and letterboxed rather than stretched, so a stray odd-sized frame never appears distorted.

H.264 itself tops out at roughly 4096 × 2304 pixels. Beyond that the size readout turns red and saving is blocked until the percentage comes down.

Saving

Save MP4… encodes the sequence, then opens a save dialog already pointing at the folder the images came from, with that folder's name suggested as the filename. Both are editable in the dialog.

The output is H.264 in a plain MP4 container, 4:2:0, with the index written ahead of the video data (the equivalent of ffmpeg's -movflags +faststart) and an explicit BT.709 colour description. That combination is what Windows Media Foundation — and therefore PowerPoint — is happiest with.

Notes

Nothing is uploaded and nothing leaves this machine. Images are read straight from disk one at a time and encoded inside this page. Memory use does not grow with the length of the sequence: only one decoded frame exists at a time, so a folder of 2000 images costs no more than a folder of 20.

Encoding uses the browser's own H.264 encoder (WebCodecs), which needs Chrome or Edge. The badge at the top right says whether it is available.
